Earlier bell recovery, historical route

This route describes the previous bell at x 1148. The final cartridge above moves it to x 1128 and supports the corrected approach shot. On the earlier cartridge, the closed gate and tabletop leave insufficient room for Kittie to stand on the floor at the right edge before the bell opens. The tested solution uses a flat throw from the left edge of the tabletop. At x 1097 with feet at y 96, pressing Right+B for one update sends ball across the table. It drops into the gap, rings the low bell from the right, and rests at x 1185.125, y 124 on the dry exit floor. Walking to the right edge and briefly settling onto the floor retrieves it. This route uses the existing flat throw, collision and pickup rules.

The first maximum attempt retained an explicit Start reset and a water failure. A supported checkpoint resumed the identical ROM and runtime without extra frames. A later fresh boot independently replayed the complete ordinary input history and reproduced 900. The input history and native recording retain the successful shot and the earlier failures.

Save identity

The published v1 save signature is 0xb98c5e87. Its first variables block is 3,584 bytes, including the VM context stacks. The compatibility reader validates that layout, reads only the validated stage unlock from the legacy save, and starts its courtyard best at zero. Current pilot saves require this cartridge's signature, score schema marker 19537, a valid unlock, and a best in the range 0 to 900 in steps of 100.

Scope of evidence

Gameplay used the public ModRetro PyBoy tools and genuine native frames. Save transfer used the installed official PyBoy 2.7 public ram_file constructor and export API because the public emulator tools do not expose SRAM transfer. All play used ordinary button inputs. Verification did not inject values into emulated memory or modify cartridge bytes. The runner, plans, captures and state logs remain available for reproduction.

These checks establish native scoring, progression and SRAM persistence. They do not establish physical Chromatic behavior, audio quality, browser close/reopen persistence, or the independent critic's judgment of difficulty and discovery. Banquet entry was checked; this verification did not replay the full banquet. The published v1 baseline remains intact.
