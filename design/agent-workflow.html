Working cycle

  1. Designer creates a whole-level brief. The art editor independently reviews the current presentation.
  2. Builder produces a playable level. The coordinator keeps changes bounded and resolves decisions.
  3. A fresh critic receives the game and user direction without the builder's walkthrough or design defense. The art editor reviews actual native frames.
  4. Builder addresses findings. Reviewers replay or inspect the affected result. Further cycles follow concrete unresolved findings, not a requirement to invent more changes.
  5. The coordinator presents the complete level, short footage, and any remaining subjective choice to the user.

Parallel reading and review are encouraged. One owner controls builds and emulator sessions at a time. Only the builder changes game files during implementation. Preserve the user's browser play state. Physical Chromatic testing remains with the user.

When the user is needed

Ask for review when the complete level is ready, or when an unresolved decision would change the game's core identity or mechanics. Handle routine implementation and review findings within the team. This workflow runs during authorized work; it does not create a background schedule.
